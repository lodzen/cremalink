cremalink.domain package

This package defines the core domain models for the cremalink library, representing the main entities like the coffee machine itself.

It exposes the primary Device class and factory functions for creating device instances, abstracting away the underlying implementation details.

Represents a coffee machine, providing methods to control and monitor it.

This class holds the device’s state (e.g., IP, model) and uses a DeviceTransport object to handle the actual communication. Device-specific capabilities are loaded from a “device map” file.

brew(beverage_id: int, recipe: bytes | None = None, profile_slot: int | None = None, accessory: int = 0) → Any[source]

Start brewing beverage_id.

profile_slot=None resolves to the last 0xA9-acked profile (current_profile); recipe=None fetches the profile-scoped recipe bytes from the republished a6f0 property — both per the FR-001 coherence rule (frame names its profile, recipe must be that profile’s). do() uses the same live-recipe path, taking beverage id, action and trailer from the stored frame and falling back to the captured recipe when the machine does not republish one.

do(drink_name: str) → Any[source]

Executes a command by its friendly name (e.g., ‘espresso’).

Map entries are decoded fields, not captured frames:

  • power (standby/wake/session_refresh) builds via build_power.

  • beverage_id entries build via build_brew. With a recipe_datapoint the recipe is fetched live from the machine’s republished profile-scoped property (0xA6) and the brew fails closed if it is unavailable; entries without one use their stored recipe hex (models with no recipe catalogue), and a recipe-less stop frame uses the default recipe.

  • Entries holding only a raw command hex are sent verbatim.

Built frames go through the session gate.

Parameters:

drink_name – The name of the command to execute, as defined in the command_map.

Returns:

The response from the transport.

Raises:

  • ValueError – If the command name is not found in the device map.

  • ConnectionError – If no recipe is available for a brew entry.

set_setting(key: str, option_index: int) → bool[source]

Write a writable setting (session-gated 0x90 + ack/read-back).

Follows protocol.md §14.5: device_connected announce (via _send_gated()) → 0x90. §14.5 woke the machine for its test; by product decision this library never wakes it — a machine in standby aborts the write with MachineStandbyError before any frame is sent. §14.5 confirmed the commits on the machine’s display and recorded no ack for them, so the ack is treated as optional: the write counts as committed when a read-back — mailbox answer or the republished dNNN backing property — shows the new value.

Returns True when the write is confirmed and False when the machine nacked it or reports a different value. Raises ValueError for unknown keys/options, MachineStandbyError when the machine is in standby and TimeoutError when neither an ack nor a read-back arrives.
